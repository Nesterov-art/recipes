# Monorec approved UX/UI implementation plan

**Goal:** Implement approved Choice B, unified palettes, Settings spacing 28px and floating tab bar, without changing data or navigation lifecycle.
**Architecture:** Retain Expo Router js-tabs and its screen wrappers. One custom tabBar renderer occupies layout space; no overlay on lists. Existing art is temporary and originals stay unchanged.
**Spec:** Stage A mockups and STAGE-A.md outside the repo, approved in conversation on 2026-10-31.

## Constraints
- No dependencies, app/EAS configuration changes, commit, push, deployment or APK; do not touch emulator-5554/AVD.
- Preserve storage, backup, model, random and recipe website import.
- RU/EN, both themes, reduced motion, keyboard and safe area.

## Review focus
- Last recipe/product can fully scroll above bar; keyboard hides bar.
- Switching tabs preserves search/draft; Choice tabPress reset and browser Back remain.
- Label widths and system text do not clip controls; Settings menus still work.
- Palette change does not remove danger/success or overwrite modal-specific states.
- Repeated taps retarget one capsule; no animation queue, reduced motion snaps.

## Decisions and evidence

- Installed SDK 58 exports `emitter`/`navigateToTab`: used real SDK types instead of the older navigation-prop example. No new navigator/dependency.
- Original no-visible-heading checks changed after review to preserve screen-reader headings clipped to 1px; user requested removal of visual labels, not loss of semantics.

- Browser focus cycle is checked for absence of hidden-tab targets and reachability of the Appearance row; it no longer assumes every browser resets sequential focus to document start after a tab click.
- Read-only review findings (side insets, iOS Large Content Viewer, Settings semantics) fixed; follow-up found no concrete blockers. Device verification remains outstanding.
