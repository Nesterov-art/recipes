# Браузерные E2E и визуальные проверки

Проверяется production web-экспорт Expo Router, а не нативная сборка. Playwright
сам собирает приложение и запускает локальный сервер на `127.0.0.1:4173`.
Сервер предназначен только для тестов. Не запускайте рядом второй экземпляр на
том же порту; уже работающий сервер намеренно не переиспользуется.

## Запуск

Нужен Node.js 22.18+; CI использует Node.js 24.13.0.

```sh
npm ci
npx playwright install chromium webkit
npm run test:e2e
npm run test:e2e:report
```

На Linux перед первым запуском: `npx playwright install --with-deps chromium webkit`.
Для интерактивной отладки: `npm run test:e2e:ui`.
Один профиль: `npm run test:e2e -- --project=iphone-webkit`.
Только функциональные тесты: `npm run test:e2e -- --grep-invert @visual`.
В PowerShell аргумент `@visual` нужно заключать в кавычки.

Профили: desktop Chromium 1440×900, mobile Chromium (Pixel 7), WebKit (iPhone 13).
Каждый тест получает отдельный браузерный контекст. Рецепты, покупки и настройки
задаются через `storageState` при его создании. Перезагрузка и новые страницы
этого контекста читают сохранённые приложением данные без повторной подстановки.
Проверки записи ждут AsyncStorage перед перезагрузкой, а затем проверяют интерфейс.
Никакие данные пользовательского браузера или опубликованного сайта не меняются.

## Что проверяется

- Покупки: ввод, объединение совместимых количеств, редактирование, отметка,
  перенос купленного вниз, настройка «Оставлять на месте», очистка и сохранение.
- Выбор ингредиентов рецепта и подбор блюд по списку покупок.
- Свайп открывает удаление; удержание с движением меняет порядок; результат
  проверяется в интерфейсе, хранилище и после перезагрузки.
- Все три профиля проверяют жесты указателем. Отдельный тест mobile Chromium
  использует настоящий браузерный touch-ввод через CDP. На desktop и WebKit
  этот дополнительный тест пропускается с объяснением. Это не проверка iOS touch.

Удаление после touch-свайпа исправлено: действие использует совместимый с
распознавателем жестов Pressable. Touch-тест больше не помечен ожидаемой ошибкой.
Кнопка удаления оформлена отдельным красным кругом с белой корзиной и подписью,
как в предоставленном референсе Почты.

Также не проходит отдельная проверка удержания и перетаскивания через trusted
touch-ввод Chromium: порядок не меняется. Она тоже помечена `test.fail`, а не
выдаётся за успешную. Перетаскивание указателем проходит во всех трёх профилях.
- Поиск по названию/ингредиентам, регистру и нескольким словам, пустой результат,
  очистка запроса, избранное, создание рецепта, тема, язык и размер текста.
- Пустая сохранённая книга (`recipes=[]`) не заполняется стартовыми рецептами.
- Манифест, iPhone meta-теги и PNG-иконки в итоговом web-экспорте.

Онбординг проверяется в `e2e/onboarding.spec.ts`: чистый профиль, три шага,
возврат назад, пропуск, завершение, пустая книга и повторное открытие вкладки.
Незавершённое знакомство остаётся доступным после перезагрузки. Отдельно
проверяются ошибка записи и повторная попытка, прямой вход в покупки, миграция
существующих данных, повтор знакомства из настроек, английский язык и крупный
текст на экране шириной 320 px. Скриншоты трёх шагов есть в обеих темах.
Старые профили (включая сохранённую пустую книгу) автоматически пропускают
первое знакомство; их данные не очищаются и не заменяются.

## Скриншоты

```sh
npm run test:visual
npm run test:visual:update
```

Эталоны хранятся в `e2e/screenshots/<platform>/<project>/` и включаются в Git.
Разделяются также тема и сценарий. Проверяются главная, покупки, форма,
настройки, крупный текст и оба пустых состояния в светлой и тёмной темах.
Дата фиксирована; часы анимаций продолжают работать. Перед снимком ожидается
готовность шрифтов; сравнение отключает анимации и скрывает каретку.

CI использует Windows Server 2025 и актуальные эталоны `win32`, проверенные
локально на Windows. Исторические Linux-эталоны сохранены отдельно, но после
изменения интерфейса 19 октября их нужно пересоздать в Linux перед использованием
для сравнения. Прежний Ubuntu WSL в текущем окружении отсутствует, поэтому CI
переведён на доступную и проверенную платформу; GitHub-прогон ещё не выполнялся.
Windows-эталоны нельзя переименовывать в Linux или наоборот. Различия шрифтов
и системных библиотек также влияют на рендеринг; после обновления окружения
различия следует просмотреть и утвердить заново.

Обновление эталонов — явное действие после просмотра результата. CI не
обновляет изображения сам и падает при отсутствующем эталоне или расхождении.
Для нового локального окружения первый `test:visual` покажет отсутствующие
эталоны; выполните `test:visual:update`, просмотрите PNG и повторите сравнение.

Отчёт находится в `playwright-report/`; различия изображений, видео ошибок и
trace первого повтора — в `test-results/`. Эти каталоги исключены из Git.
В CI отчёт и результаты сохраняются как artifact на 14 дней. Для trace без
повтора локально: `npm run test:e2e -- --trace on`.

## Safari, iPhone и PWA

Профиль iPhone эмулирует размеры, user agent, плотность пикселей и touch-возможности.
WebKit Playwright не является Safari, установленным на iPhone, и не проверяет
нативные экраны Expo. Наличие манифеста не доказывает работу без сети: service
worker в приложении пока отсутствует, офлайн-проверка не заявлена.

Перед выпуском вручную на реальном iPhone:

1. Открыть приложение в Safari и добавить на домашний экран; проверить оба режима.
2. Проверить safe area, нижнюю панель и Home Indicator при прокрутке и повороте.
3. Ввести поиск и покупку с экранной клавиатурой; убедиться, что поля и кнопки
   доступны, клавиатура закрывается, высота экрана восстанавливается.
4. Свайпнуть строку влево и удалить её; удержать другую строку, перенести её,
   включая автопрокрутку длинного списка. Проверить отсутствие случайных отметок.
5. Проверить купленные позиции и оба режима их размещения.
6. Закрыть Safari/PWA, открыть повторно и проверить рецепты, покупки, порядок,
   отметки и настройки. Перезагрузка тестовой страницы не заменяет этот шаг.

Официальная документация:
[эмуляция](https://playwright.dev/docs/emulation),
[браузеры и отличие WebKit от Safari](https://playwright.dev/docs/browsers),
[сравнение скриншотов](https://playwright.dev/docs/test-snapshots),
[Expo web export](https://docs.expo.dev/more/expo-cli/).

## Фокус поиска на iPhone

В web-версии размер шрифта поиска ограничен снизу 16 CSS px, в том числе
при уменьшенном системном шрифте. Масштабирование жестом сохранено.

Ручного переключателя размера текста больше нет. Старое поле `textSize` в
настройках игнорируется и удаляется при следующем сохранении. Тема, язык,
покупки и рецепты сохраняются. `search-focus.spec.ts` оставляет три старых
значения только как сценарии миграции и проверяет повторный фокус и геометрию.

`system-text.spec.ts` проверяет обновление текста при изменении базового шрифта
браузера, нижнюю границу поля поиска и сохранность других настроек после миграции.
В нативных сборках масштаб применяют сами Text/TextInput; дополнительный множитель
равен 1. На web скрытый измеритель использует системный `-apple-system-body`,
если он поддерживается, иначе `1rem`; ResizeObserver отслеживает изменение.
Эталонные скриншоты крупного текста моделируют предпочтение браузера, а не
доказывают работу Dynamic Type на настоящем iPhone.

На реальном iPhone изменить размер текста в системе, вернуться в установленную
PWA, несколько раз нажать на поиск, ввести запрос и закрыть клавиатуру. Проверить
размер текста и отсутствие автоматического зума. Повторить после перезапуска PWA.

## Клавиатура и высота PWA

Высота root учитывает `visualViewport.height + visualViewport.offsetTop`, когда
клавиатура сдвигает видимую область. Обрабатываются resize и scroll viewport.
Тест `keyboard-viewport.spec.ts` воспроизводит сдвиг, проверяет заполнение области
до нижней границы, поиск и восстановление после закрытия клавиатуры. Это модель
событий Safari; окончательная проверка экранной клавиатуры нужна на iPhone.

## Резервная копия рецептов

`e2e/backup.spec.ts` проверяет скачивание реального JSON и его повторный импорт,
выбор файла через кнопку, предварительный просмотр и отмену, сохранение
избранного и истории, защиту текущих данных при конфликте, повторы, отказ записи,
повторную попытку и восстановление после открытия новой вкладки. Невалидный JSON,
повреждённые записи, неизвестная версия и размер свыше 5 МБ отклоняются целиком.
Логика формата и объединения проверяется в `src/utils/recipe-backup.test.mjs`.

Рецепты и метаданные теперь сохраняются одним авторитетным снимком `recipe-book-v1`,
чтобы импорт не мог сохранить рецепты отдельно от их истории. При первом открытии
читаются прежние `recipes` и `recipe-meta-v1`; они продолжают обновляться как
совместимые зеркала. Покупки, настройки и состояние знакомства не импортируются.

Выбор файла и системное меню iOS нельзя считать проверенными на устройстве по
результату эмуляции WebKit. На реальном iPhone в установленной PWA нужно проверить
«Выгрузить в файл → Сохранить в Файлы», отмену системного меню, повторный выбор
сохранённого файла и появление рецептов после перезапуска. Нативные сборки пока
не показывают блок импорта/экспорта: подключение Expo DocumentPicker, FileSystem
и Sharing отложено до восстановления доступа к npm и подготовки нативной версии.
